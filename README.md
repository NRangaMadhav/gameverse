# GameVerse India — Multi-Agent Multimodal RAG Research Assistant

A compact research assistant for India's gaming ecosystem. A LangGraph planner routes each
question to local report retrieval, live web research, or both; a synthesis agent returns a
grounded brief with source references.

## Included

- Streamlit research UI and FastAPI endpoints.
- LangGraph planner, local retrieval, web research, and synthesis nodes.
- PyMuPDF ingestion for PDF text, detected tables, and NVIDIA-generated figure descriptions.
- NVIDIA chat/vision and embedding models with ChromaDB vector storage.
- Parallel web search exposed as an MCP tool.
- Optional PostgreSQL persistence for completed research sessions.

## Setup (Windows PowerShell)

Run these commands from this project directory. The `gamerverse` virtual environment is
already created if this project was generated by the setup assistant.

```powershell
.\gamerverse\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Edit `.env` and set `NVIDIA_API_KEY` and `PARALLEL_API_KEY`. The keys shared in the original
request are deliberately not stored in project files; rotate them before use. Set
`DATABASE_URL` only if PostgreSQL is available, for example:

```text
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/gameverse
```

The NVIDIA API key is required for the planner, synthesis, embeddings, and visual descriptions.
The default chat/vision model is `google/diffusiongemma-26b-a4b-it`; the embedding model remains
`nvidia/nv-embedqa-e5-v5` for vector search. Confirm both models are enabled for your NVIDIA API
account. The Parallel key is required when the planner routes a question to live web research.
NVIDIA chat and vision requests use a 180-second timeout by default. To adjust it, set
`NVIDIA_REQUEST_TIMEOUT_SECONDS` in `.env` and restart the app.

## Index the provided reports

The included PDFs are in `pdfs`. Ingestion extracts text and tables and describes embedded
figures using the configured NVIDIA vision model. This first run can take several minutes.

```powershell
python -m app.ingest
```

Ingestion is repeatable: each PDF's previous vectors are replaced when it is re-indexed.
The generated Chroma database is stored in `chroma_db` and is ignored by Git.

## Run the app

Start Streamlit:

```powershell
streamlit run streamlit_app.py
```

Or start the API:

```powershell
uvicorn app.api:app --reload --host 127.0.0.1 --port 8000
```

API routes:

- `GET /health` — service health check.
- `POST /research` — JSON body `{"question": "..."}`.
- `POST /ingest` — index PDFs from the project's `pdfs` folder.

API documentation is available at `http://127.0.0.1:8000/docs`.

## Error handling

Missing credentials, malformed planner output, upstream errors, PDF parsing issues, empty
indexes, and PostgreSQL write failures are surfaced rather than replaced with fabricated
results. Streamlit displays actionable setup guidance; API failures return an HTTP error and
the server logs the underlying exception.

If Streamlit reports that NVIDIA took too long to respond, wait briefly and submit the
question again. If it keeps happening, check NVIDIA service/API-key status and increase
`NVIDIA_REQUEST_TIMEOUT_SECONDS` in `.env`; restart Streamlit after editing the file.
